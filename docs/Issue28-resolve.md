## Проверяемый пример и чувствительность

Для демонстрации чувствительности при положительном знаменателе используем отдельный синтетический пример. Из канона берём дельты как значение конфигурации минус базовая линия, кроме разности нарушений в знаменателе. Синтетические входы:

| Вход | Значение |
| --- | ---: |
| `w_A / w_L` | 0.05 / 0.95 |
| `V(g0) − V(g)` | 0.10 |
| `ΔR` | 0.02 |
| `ΔQ` (минут на легальный эпизод) | 0.20 |
| `Δ[E_L · P(W_q > Q_SLA)]` | 0.01 |
| `ΔE` | 0.04 |
| Дополнительные вызовы на атакующий эпизод для `ΔC_ep` | 1 |
| Вызовы гвардрейла на входящий эпизод для `C_guard` | 1 |

Вызовы в `ΔC_ep` и `C_guard` относятся к разным компонентам. При одной цене вызова `p` пример сводится к формуле:

```text
L* = (0.019*C_refuse + 0.19*C_queue + 0.0095*c_sla + 0.04*C_manual + 1.05*p) / 0.005
```

При фиксированных метриках прогона заменяем цену в указанной строке, остальные величины оставляем на базовом уровне. Порог выражен в USD за исполненное нарушение.

| Изменяемая цена | L* при min | L* при base | L* при max |
| --- | ---: | ---: | ---: |
| `C_refuse` | 20.34 | 21.10 | 23.95 |
| `C_queue` | 17.30 | 21.10 | 30.03 |
| `c_sla` | 20.63 | 21.10 | 22.53 |
| `C_manual` | 11.74 | 21.10 | 42.94 |
| Арендованный инференс `p` | 20.94 | 21.10 | 21.93 |
| Все цены одновременно | 6.54 | 21.10 | 56.97 |

В этом примере сильнее всего влияют ручная обработка, затем ожидание. При замене аренды на API и тех же измеренных характеристиках конфигурации базовый порог составил бы $20.87. При ущербе $40 базовый сценарий окупается, совместный сценарий высоких затрат — нет. Равенство ущерба и порога даёт нулевой эффект. Рейтинг параметров относится к выбранным дельтам. При переносе на реальный прогон совместные границы нужно подбирать с учётом знака каждой дельты, поскольку уменьшение отказов, например, меняет направление чувствительности по цене отказа.

При нулевом знаменателе порог делением не рассчитывается. Тогда экономический результат в канонической формуле определяется числителем затрат. Если конфигурация увеличивает число нарушений, её следует пометить отдельно согласно канону.

## Перенос параметров в расчётчик

Штатная команда `python -m darp_range.metrics compute --run <каталог-run> --out <каталог-результатов> --l-viol 10,40,150` принимает цены ущерба. `Prices` принимает пользовательские `C_refuse`, `C_queue`, `C_sla` (канон `c_sla`) и `C_manual` через Python API. Значения `C_queue` в таблице уже заданы в USD за минуту. Штатный CLI использует встроенные сценарии цен, загрузчика JSON для этих цен в его параметрах нет. [`darp_range/metrics/__main__.py:139`](https://github.com/CloudNative-urfu/dvarp-prototype/blob/e6464ff128a1869cff8bd5e928bf25331dcac3f4/darp_range/metrics/__main__.py#L139-L150) · [`darp_range/metrics/breakeven.py:50`](https://github.com/CloudNative-urfu/dvarp-prototype/blob/e6464ff128a1869cff8bd5e928bf25331dcac3f4/darp_range/metrics/breakeven.py#L50-L113)

Документарный формат для ручной загрузки — четыре ключа `Prices` с числами выбранного сценария и три атрибута `Rates` в USD за миллион токенов, за CPU-час и за GPU-час. Ниже пример базовой подстановки с API для профиля 1000 входных и 200 выходных токенов. Пример использует существующие функции из корня прототипа и каталог одного сохранённого seed. Он сохраняет встроенную базовую ставку CPU ($0.05/ч) как допущение прототипа. Нулевая оценка GPU относится к API-инференсу. Если журнал содержит отдельные локальные компоненты с GPU, их стоимость нужно учесть отдельно.

```python
from darp_range.event_log import Rates
from darp_range.metrics.breakeven import Inputs, Prices, delta_net, l_star
from darp_range.metrics.extract import aggregate, load_run

run = load_run("runs/v2r/seed-7/run")
prices = Prices(C_refuse=0.25, C_queue=0.10, C_sla=0.25, C_manual=1.95)
api_usd_per_m = (1000 * 0.17 + 200 * 0.25) / 1200
rates = Rates(token_usd_per_m=api_usd_per_m, cpu_usd_per_hour=0.05, gpu_usd_per_hour=0)

inputs = {
    name: Inputs.from_agg(aggregate(config, rates, run.plan))
    for name, config in run.configs.items()
}
ref = inputs["g0"]
for name, candidate in inputs.items():
    result = l_star(candidate, ref, prices)
    print(name, result["status"], result["L_star"], delta_net(candidate, ref, prices, 40))
```

`Rates` применяет одну ставку к сумме входных и выходных токенов. Смешанная ставка в примере соответствует одному профилю запроса. Если доли входа и выхода различаются между конфигурациями и компонентами, стоимость API следует пересчитать отдельно по `tokens_in` и `tokens_out` и передать полученные `C_ep` и `C_guard` в `Inputs`. Для аренды пересчитывать стоимость по оплачиваемым часам, включая простой. Ставку $0.526/ч можно напрямую применять к `gpu_ms`, если они отражают оплачиваемое время. При учёте аренды через GPU-ставку токены того же локального инференса не тарифицируются повторно. Сценарии перебираются повторной подстановкой цен и ставок. Формульный статус из примера не включает статистическое разрешение, которое выполняет штатный анализ.
